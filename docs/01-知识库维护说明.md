# 知识库维护说明

`docs/` 是 Code Ark 工作箱的纯文档目录，既可直接用编辑器浏览，也可直接作为 Obsidian vault 打开，通过 Git 协作维护。阅读和维护无需安装额外构建工具。

## 1. 目录职责边界

| 目录 | 唯一维护内容 | 修改原则 |
| --- | --- | --- |
| `docs/requirement/` | 原始需求、确认决策 `Cxx`、待定边界 `Qxx` | 保留原始表述与确认来源，不删改历史记录，增量决策以新条目追加 |
| `docs/research/` | 外部工具拆解、版本实测、仓库现状盘点 | 明确标注核查日期与证据来源；采纳后写入 `design` 才生效 |
| `docs/design/` | 架构、协议、状态机、数据安全与边界合同 | 遵循 [设计模板](templates/01-设计模板.md)，标注已确认/建议/待定 |
| `docs/prd/` | 用户故事、需求清单与验收标准 | 一份 PRD 只能链接唯一来源 `design`，不自创技术方案 |
| `docs/plan/` | 精确文件路径、接口签名、单元测试与 CI 验证 | 一份 Plan 只能链接唯一来源 `prd`，不把未执行步骤写成已完成 |
| `docs/templates/` | 写作模板 | 参考 `business/lucky/docs/templates` 体系维护 |

## 2. 根规范与现有服务文档关系

- 仓库根目录 [README.md](../README.md)、[README.en.md](../README.en.md)、[CONTRIBUTING.md](../CONTRIBUTING.md)、[AGENTS.md](../AGENTS.md) 以及各服务目录内的 `README.md` 仍留在原位维护，不在 `docs/` 内复制正文。
- `docs/` 内引用根规范或具体服务的 `docker-compose.yml` 时，统一使用相对路径（如 `../../temporal-start-local/docker-compose.yml`）。

## 3. 检查与校验

每次增删或调整文档后，核对以下四项：
1. 各子目录 `00-*导航.md` 与 [00-文档导航.md](00-文档导航.md) 的链接与编号是否同步；
2. 每份 `PRD` 是否仅指向唯一 `design`，每份 `Plan` 是否仅指向唯一 `PRD`；
3. 版本号、文件路径、命令与测试状态是否均有实测依据，未运行的检查标注为“未执行”；
4. 在仓库根目录执行 `git diff --check`，确保无尾随空格或行尾错误。
