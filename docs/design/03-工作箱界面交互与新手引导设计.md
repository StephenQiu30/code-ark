# 03 工作箱界面交互与新手引导设计

状态：已对齐基线，待进入实施。依据：[需求 01](../requirement/01-工作箱产品总览与核心诉求.md)（`REQ-02`、`C03–C05`）、[需求 02](../requirement/02-服务依赖与新手使用场景清单.md)（`REQ-03`、`REQ-04`）、[调研 01](../research/01-Mac游戏工具箱产品交互与架构拆解.md)。

## 1. 摘要

借鉴 `mac-gaming-toolbox` 的双栏侧边栏信息架构与产品温度，设计 Code Ark 工作箱的前端交互体系：左侧固定导航覆盖“工作台 / 运维与诊断 / 教程与设置”，主区以“7 大场景启动台 + 17 个服务目录 + 四标签详情抽屉 + 脱敏诊断导出 + 宿主机/容器连接教程”构成闭环，帮助编程新手从“不知道怎么起服务”无缝走到“复制配置跑通业务代码”。

## 2. 参与者

- **前端工作台（React 19 + TypeScript + Tailwind CSS）**：承担状态展示、引导交互、表单校验、剪贴板复制与流式日志呈现；所有敏感数据存储与 Docker 执行全部下沉到 Rust IPC，不在浏览器侧持久化密码。
- **新手开发者 / 老用户**：按各自熟练度选择“场景一键启动”或进入单服务详情精细调参。

## 3. 背景

- 编程初学者面对 17 个服务往往面临三个“临门一脚”障碍：不知道该装哪几个、不知道登录账号密码/控制台 URL、把容器网络名和宿主机 `127.0.0.1` 搞混（`AGENTS.md` 与根目录 `README.md` 均特别强调过此点）。
- `mediacrawler-start-local` 属于宿主机 Python 工具而非容器服务，也需被优雅纳入工作箱而不制造“为什么启动不了容器”的误解。

## 4. 目标

- **可检查结果**：
  1. 双栏侧边栏与全局顶部状态条实时展示 Docker 运行时健康状态、VM 内存与运行服务计数；
  2. 默认首页即呈现 7 大开发场景预设与实时分步执行进度条（`StepProgressEvent`）；
  3. 每个服务均支持四标签详情抽屉（`连接与入口` / `可视化配置` / `实时日志` / `依赖与重置`），默认掩码显示密码并区分宿主机与容器内连接代码片段；
  4. 内置 `MediaCrawler` 宿主机检查与指引、以及一键导出 **100% 脱敏**的诊断压缩包。
- **Anti-Goals**：不能在前端页面、截图导出或诊断包里暴露明文密码（默认掩码，仅用户显式点击切换可见）。

## 5. 使用场景

- 场景 1（新手首日）：打开工作箱看到 Docker 未运行，环境体检提示引导开启 Docker Desktop；就绪后点击“Java 微服务标准套组 → 一键启动”，看着进度条走完后直接在服务详情页点开 `http://127.0.0.1:8840` 登录 Nacos，并复制 Spring Boot `application.yml` 片段。
- 场景 2（遇到报错求助）：新手启动失败，点击“环境体检 → 导出脱敏诊断包”，得到隐藏了所有 `.env` 密码的报告文件发给他人排障。

## 6. 价值

- 把分散在 18 份 README 中的端口、默认密码、控制台链接、宿主机与容器连接差异聚合到单窗口内；
- 让新手在 1 分钟内完成从安装到代码连库闭环。

## 7. 方案

### 7.1 界面骨架（参考 `mac-gaming-toolbox` `AppSidebarView`）

```text
+----------------------------------------------------------------------------------+
|  Code Ark 工作箱             [Docker: 运行中 | VM 内存 12.0 GB]   [运行中 2/17]   |
+-----------------------+----------------------------------------------------------+
|  工作台               |  主内容区                                                |
|   [*] 场景启动台 (7)  |   - 场景预设卡片 + 实时拓扑执行步进器                      |
|   [ ] 全部服务 (17)   |   - 或 按4大类分组的服务卡片矩阵                         |
|  运维与诊断           |                                                          |
|   [ ] 环境体检        |  右侧滑出详情抽屉（430px，按需展开）：                   |
|   [ ] 端口与外部冲突  |   [连接与入口] | [可视化配置] | [实时日志] | [依赖与重置] |
|  教程与设置           |                                                          |
|   [ ] 连接指南 & 教程 |                                                          |
|   [ ] 工作区设置      |  （底部独立入口，对齐 mac-gaming-toolbox 设置布局）        |
+-----------------------+----------------------------------------------------------+
```

### 7.2 核心视图与交互规范（设计建议）

1. **场景启动台（Launchpad）**：展示 7 个场景卡片（含所含服务列表、预估内存提示与“一键启动”按钮）；点击启动后在顶部展开实时分步执行进度面板，支持点击任意服务标签直达详情。
2. **全部服务目录（Catalog）**：按 `数据与存储`、`消息、工作流与调度`、`治理、搜索与观测`、`内容与搜索 API` 四大类展示 17 个服务卡片。卡片状态徽标枚举：`健康运行`、`启动中`、`已停止`、`未初始化`、`外部运行中 (只读观察)`、`端口冲突`。
3. **四标签服务详情抽屉（Service Detail Drawer）**：
   - **Tab 1 · 连接与入口（默认打开）**：Web 控制台一键外链（使用 `@tauri-apps/plugin-opener`）、端口列表、有效用户名与默认掩码密码（`••••••`，点击小眼睛按需明文显示）、**宿主机直连代码片段**（`127.0.0.1`）与**容器内连接片段**（明确警示容器内禁止使用 `localhost`）；若为 `ExternalObserve` 状态则置顶展示冲突处理与“替换接管”入口；
   - **Tab 2 · 可视化配置**：中文友好的表单字段（替代晦涩环境变量名）、字段旁“随机生成安全密钥”按钮、端口冲突行内实时提示、`rocketmq` 宿主机直连开关、`seata`/`xxjob` 联动内置 MySQL 开关；
   - **Tab 3 · 实时日志**：消费 Rust `LogLineEvent` 流式日志，支持关键词过滤、暂停滚屏与一键复制报错段；
   - **Tab 4 · 依赖与重置**：前置/下游依赖关系展示、数据持久化路径（附一键打开文件夹）、以及需**输入服务名确认**的重置数据弹窗（准确提示影响范围与数据库级联警告）。
4. **环境体检 & 脱敏诊断导出**：
   - 检查项：Docker CLI 路径、Daemon 连通性、VM 内存（标明 Elastic 6 GB 门槛）、工作区剩余磁盘、端口占用扫描；
   - 导出诊断包：收集 OS 版本、Docker 信息、端口状态、脱敏后配置结构（所有敏感变量及日志中命中的密钥全量替换为 `***REDACTED***`）与各运行服务最近 100 行日志。
5. **连接指南 & 宿主机工具中心（Guide Hub）**：
   - 专题 1：给新手的《本地跑代码 vs 容器跑代码网络地址区别》图解；
   - 专题 2：`MediaCrawler` 宿主机工具卡片（自动检测本机 `git` / `uv` 与安装目录状态，展示固定 commit `380b426000aac3d612837ed72c99808347dc94c9` 及 `hotkey-safe.patch` / `hotkey-safety-protocol.patch` 引导与安全操作提醒）；
   - 专题 3：macOS 未公证安装包首次打开提示（对应 `Q01`，对齐 `mac-gaming-toolbox` README 处理方式）。
6. **工作区设置（Settings）**：工作区数据路径展示与切换、界面语言切换（简体中文优先 / English）、Docker CLI 路径覆盖。
