# 03 工作箱界面交互与新手引导设计

状态：**源码实施中，完整实机与发行验收待完成**（2026-11-12）。来源：[需求 01](../requirement/01-工作箱产品总览与核心诉求.md)、[需求 02](../requirement/02-服务依赖与新手使用场景清单.md)、[审查报告](../research/04-一键启动工具箱设计完整性审查.md) `ARK-07/09/10/11/12/13`。保留双栏工作台及7场景，默认先提供轻量、可验证的首次成功路径。


实施状态：已开始按本合同开发，当前实现、验证和剩余项见 [首阶段执行记录](../research/06-工作箱首阶段实施与验证记录.md)。源码检查、隔离 Redis 和最终安装包是独立证据，不表示全量功能已交付。
## 1. 摘要

面向新手的交付闭环为“安装并打开应用 → Docker就绪 → 选场景 → 自动配置和依赖初始化 → 实际连接验证 → 复制客户端配置 → 安全停止/再次启动 → 故障可恢复”。不要求用户安装Git、克隆仓库、手改`.env`、导入SQL或先安装Node/Rust；业务语言工具链只在用户选择运行示例时检查和引导。

双栏与场景卡片作为信息组织方式，不复制参考产品的全部功能。沿用React/TypeScript/Tailwind，界面组件优先使用项目统一的简单组件系统；不为展示运行状态引入另一个管理后台。

## 2. 参与者

- 新手：先完成一个Redis验证，再按项目选择组合；理解服务就绪与业务客户端接入的区别。
- 日常开发者：复用已有数据库、配置端口、观察日志、应用变更和处理恢复。
- 前端：呈现后端权威状态和可执行动作，不凭按钮点击/HTTP首页生成Ready，不在浏览器存储秘密。
- 发行维护者：验证安装包、镜像、探针、示例与用户指引，发布真实支持矩阵。

## 3. 背景

17套服务的复杂度不同，首页铺满服务不能替代首次引导。旧设计的“1分钟安装到连库”“100%任意日志脱敏”及仅应用内的首次打开提示缺乏可验证边界；本轮改为明确的步骤、可恢复状态与发行门禁。会话原型未入仓库，不再作为实施依赖；以本文件文本布局和状态表为准，未来归档原型仅作辅助。

## 4. 目标

- Docker未就绪时，用户知道缺什么、去哪安装/启动、如何重新检测；就绪后单次启动动作完成全部约定基础设施准备。
- UI明确草稿、应用中、服务就绪、等待业务客户端和失败状态，所有实际连接参数由同一EffectiveConfig生成。
- 保留17服务、7场景和MediaCrawler指南；不将业务Worker/执行器或CDC转发代码宣称为已自动部署。
- 非目标：代替系统安装器/管理员权限、默默调整Docker全局设置、支持任意旧SDK、无网络首次拉取镜像。

## 5. 使用场景

1. 完全新机器：在下载页看到正确OS/CPU安装包与前置条件，完成安装/首次打开后环境助手指导Docker；缺少引擎时不出现误导性“启动成功”。
2. Docker已就绪：点击“先试运行Redis”，进度显示真实阶段，内置连接测试成功后复制地址；可停止、重开应用再启动，测试数据保留。
3. 用户选择MySQL场景并有旧数据库：在一次连接授权中确认复用和专属初始化范围，后续一键复用，不要求停止旧容器。
4. 下载超时或导入中断：保留已启动依赖、定位失败步骤，可复检后重试或只停止本次新建服务；不会用“重置全部数据”当默认修复。

## 6. 价值

按用户目标展示下一步，减少理解Docker细节的需要。正确反馈比固定耗时承诺更有用；首次拉取、构建和系统前置耗时均明确显示。

## 7. 方案

### 7.1 首次安装与环境助手

下载页、发行说明与包内离线指南包含同一版本的OS/CPU、签名/公证、Docker要求、校验和、安装/卸载、数据路径、支持限制及排错入口。首次打开被系统拦截的说明必须在应用外可见，不能要求先进入应用找教程；签名/公证状态如实显示，不指导全局禁用系统安全能力。

流程：`Welcome → EnvironmentCheck → RuntimeSetupRequired | ReadyToStart → FirstService → ConnectionVerified → Workspace`。默认只请求启动一个Redis；用户可跳过教学进入目录，不能跳过后端门禁。

| 环境问题 | UI内容与动作 | 复检后的出口 |
| --- | --- | --- |
| Docker未安装 | 按OS/CPU链接官方安装指引，说明不由工作箱内置引擎 | “已安装，重新检测” |
| 已安装但未启动 | 已检测的运行时与“打开运行时”按钮，仅启动可信已安装应用 | 等待daemon，显示可取消进度 |
| Windows WSL2/虚拟化/容器模式不符 | 对应步骤及运行时设置入口，说明管理员或重启要求 | 重新检测Linux containers |
| Linux socket权限/运行库缺失 | 按支持发行版给具体步骤，提供复制命令，不后台提权 | 重新登录/安装后复检 |
| Compose过旧/目标不支持 | 最低能力、当前版本/目标、修复入口 | 保留原选择，不静默切全局context |
| 端口/内存/磁盘/代理问题 | 实际需求、冲突来源、可用值及运行时设置/修改端口入口 | 重新检测；未知容量单独显示 |

允许用户为镜像下载配置运行时代理的指引；工作箱不擅自改daemon代理或替用户选择未知镜像站。镜像首次需联网，离线仅能使用已验证缓存；超时、取消和重试遵循设计02，不承诺固定一分钟完成。

### 7.2 页面结构与场景

左侧“工作台（概览/场景启动台/全部服务）”“运维（环境体检/运行任务/端口与日志）”“资源（使用指南）”；设置与主题入口固定底部。采用官方shadcn SidebarProvider/Sidebar/SidebarInset布局，支持折叠与移动端Sheet。顶部只保留侧栏触发器和当前页名称，移除Docker目标、连接徽标与数量摘要；运行时详情放入设置/环境体检，异常与操作消息统一使用全局Sonner提示，服务状态仍来自后端快照。

首页默认推荐Redis最小闭环、最近使用的实例和两个项目入口；场景启动台保留全部7场景。场景使用无边框Item展示服务、依赖复用与资源提示，进入后查看数据位置；点击只查看，显式“启动”才运行。`search-observability` 提供Elastic、Monitoring或同时启动的明确选择；消息场景明确当前选择的队列，默认Kafka，不同时自动启动全部替代队列。

| 场景ID | 基础设施范围与最小教程结果 | 明确由应用提供的部分 |
| --- | --- | --- |
| backend-mysql | MySQL/Redis/MinIO，复制SQL连接及S3对象读写示例 | 实际应用API |
| backend-pgsql | PG/Redis/MinIO，连接PG并完成测试查询 | Agent/向量扩展按应用另行配置 |
| java-microservices | MySQL/Redis/Nacos/Sentinel，示例注册/配置读取与限流请求 | 真实微服务及客户端集成 |
| java-distributed | MySQL/Seata/XXL-Job，示例事务回滚与调度任务结果 | 业务undo_log、执行器和业务代码 |
| workflow-temporal | 复用PG、启动Temporal，测试Namespace可见 | 用户业务Worker；教学提供可运行测试Worker示例 |
| cdc-messaging | MySQL/Canal/选定消息系统，分别验证变更订阅和消息收发 | 默认不部署Canal→队列转发；如教程展示该链路，需单独运行明确标注的示例桥接代码 |
| search-observability | ES/IK/日志或Monitoring，测试日志检索/指标查询 | 真实业务采集器与采集目标 |

### 7.3 服务详情与连接片段

四标签保留：“连接与入口”“配置”“日志”“依赖与数据”。宿主机/容器片段由后端返回实际已应用generation的 `ConnectionView`；同时显示草稿尚未应用的区别。容器连接片段包含需要加入的真实网络及别名，不能只写一个在其他网络不可解析的服务名；Linux默认不借 `host.docker.internal` 访问回环发布的数据库。

- 控制台按钮仅在对应组件可访问时启用；后台未就绪时可打开页面用于排错，但明确标“后台尚未连接”，不修改Ready状态。
- 账号和秘密默认掩码；只有显式显示/复制才向前端提供该字段短期值，离开详情后清理；不写localStorage、分析日志或截图导出。
- RocketMQ默认展示5.x Proxy endpoint、匹配SDK和样例；旧版Broker直连限制明确标在高级信息中，不提供误导的回环广播开关。
- 凭据失配提供“验证/更新连接凭据”；v1对已初始化数据库账号禁用随机生成/服务器密码轮换，包括自有账号。只接受经真实认证证明已生效的新连接值，外部账号不显示“自动修复密码”。

`GuideSpec { guide_id, service_id, client_family, locked_client_version, required_tools, source_files, invocation, expected_output, cleanup, scope_notice }`。实施时为选定客户端填入经过真实验证的精确版本和可复制命令；不能把含未说明占位符的片段标为“复制即用”。示例随应用打包，先提供内置连接测试，运行源码示例才检查语言工具链并引导。客户端样例不携带真实秘密，运行时注入，示例操作只在教程测试命名空间/记录上执行。

### 7.4 操作反馈与恢复

前端消费设计02的ServicePhase和事件seq；断线、应用重开或切换页面先取快照再续订事件，不能丢掉进行中任务或重复提交。展示当前步骤、已耗时、deadline、可取消性、失败原因和保留资源；明确“正在运行但未验证”“等待客户端”“降级”“需要修复”。不靠颜色单独表达状态。

配置以“保存草稿”“预览并应用”区分；应用前展示重建/依赖影响，正在运行的旧配置仍可查看。失败按钮只重试后端允许的步骤；有数据格式迁移时没有自动降级按钮。停止场景展示被其他场景共用而保留的服务，手动停止依赖时展示受影响者；外部连接不开放生命周期操作。

重置弹窗消费不可变ResetPlan，列准确数据库、卷、路径、影响和有效期；输入服务名仅作为用户确认，后端还要复核plan ID/指纹/归属。资源变化或过期需重新计划。外部数据库没有整库重置入口；基础库包含未知业务数据时显示禁用原因。创建新托管实例清楚说明旧数据不会自动迁移，提供逻辑导入/导出指引。

工作区切换前展示旧工作区仍运行实例，切换不自动搬数据或停服务；v1工作区位置变化使用“打开另一工作区”或明确离线迁移指南，不提供看似即时但未迁移数据的开关。

### 7.5 诊断与教程

诊断默认只导出白名单字段：版本、目标类型/匿名ID、错误码、步骤状态、探针结果、端口、资源归属摘要。拒绝 `.env`、展开Compose、进程命令行、认证头、完整Docker inspect及用户主目录原文。运行日志默认不带出；用户选定服务并预览后才可附加限定100行，经过结构化字段脱敏、已知秘密及URL编码/常见DSN表示处理，剩余高风险内容可手工排除。不能承诺任意日志100%脱敏。

实时日志和“复制错误”同样走后端脱敏，不把原文秘密先送到前端再遮罩。秘密值为空、短值、重叠、含Unicode/编码时不误替换正文；未知Token模式匹配是补充，不能作为已证明无泄露的依据。导出结果含所选范围与用户确认，不自动发送给任何人。

教程包含Docker安装/复检、存储与备份、宿主机/容器网络、各场景最小示例与成功输出、停止/重建、配置恢复；MediaCrawler单独标“宿主机工具，需要Git/uv”，固定commit及补丁校验，缺工具时给步骤，不混入17服务启停。

### 7.6 IPC与状态来源

当前 `desktop.rs` 作为类型化命令层，只暴露类型化后端动作：目录、环境快照、环境复检、绑定发现/验证/授权、场景/服务启停、草稿验证/应用、重置计划/执行、操作取消/重试、连接视图、日志、诊断预览/导出、指南和工作区选择。v1不暴露已初始化数据库账号轮换。错误和事件共用设计01的schema，不从浏览器直接执行任意Docker、SQL或文件路径。

`DashboardSnapshot { target, services, operations, bindings, sampled_at }`、`ConnectionView { instance_id, applied_generation, host_endpoints, container_endpoints, required_networks, credential_handles }`、`ConfigDraftView { draft_id, base_generation, fields, validation_errors, apply_impact, requires_rebuild, preflight }`、`DiagnosticsPreview { preview_id, sections, excluded_fields, risk_flags }`。揭示秘密为单独命令并由当前详情范围校验；文件/URL打开仅接受后端生成且通过白名单校验的路径或官方入口。

### 7.8 前端与发行技术基线

依[技术选型核验](../research/05-完整技术选型与服务制品核验.md)，候选React/ReactDOM19.3.1、TypeScript6.0.3、Vite8.3.8/plugin-react6.3.0、Tailwind/Vite插件4.3.5、shadcn CLI4.23.0、radix-ui1.8.1（2026-11-13按当前设计与用户要求替换Base UI）；测试Vitest5.1.0/Testing Library React16.3.3、DOM10.4.2、user-event14.6.10/jsdom31.0.0。构建候选Node24.22.3/pnpm12.18.0，已建立package/锁文件并完成本机联合编译与组件测试；原生WebView兼容另行验收。

统一shadcn Radix组件源码（radix-nova），组合触发器使用asChild，选择控件与对话框使用Radix原生键盘/焦点语义；不默认增加SSR、Redux、Monaco、终端或大型图表。全局target/workspace/快照使用Context/useReducer起步，状态仍来自Rust；表单规则取catalog与后端，前端不再手工维护一套完整DTO模型。公共类型由ts-rs导出并与serde夹具回归，不能用TypeScript类型代替后端验证。

Tailwind4要求Chrome111/Safari16.4/Firefox128级别的对应CSS能力。macOS14起点按Safari17能力设置发行JS target，Windows用实测WebView2；Linux记录真实WebKitGTK引擎版本并验证所用CSS，4.1仅为API包名。Vite开发esnext或jsdom通过不能证明原生WebView兼容；Linux在最老支持基线22.04构建、22.04/24.04分别运行，不能在新glibc构建后直接声称旧系统支持。

低频状态保留StepProgressEvent+seq/快照。日志使用`start_log_stream(LogStreamRequest, Channel<LogBatch>) -> LogStreamHandle`，请求为instance_id与受限tail_lines，`LogBatch { stream_id, batch_id, from_seq, lines, dropped_count }`。Rust与前端每流均最多2000行/2MiB；完整batch序列化UTF-8 JSON最多64KiB且最多100行、每秒最多10批；单行序列化后最多16KiB，UTF-8边界截断并标注。不是只限制“已显示行数”而放任待发送/待处理队列增长。

`LogStreamHandle { stream_id, phase }`，`phase=Active|AwaitingConsumer|Expired|Stopped`属于日志订阅状态，不改变服务Ready状态；batch_id/ACK只在当前stream内有效。操作/服务快照和日志状态分别读取，过期状态不能靠一次强制额外Channel发送突破信用窗。

应用层信用窗最多**2个未确认batch且总序列化字节不超过128KiB**；发送前登记pending并扣credit，到达任一上限不再调用Channel.send。前端把批次应用并完成渲染提交后调用`ack_log_batch(LogAck { stream_id, batch_id })`；后端核验所属窗口/scope及真实pending，重复/未知/旧stream ACK不增加credit，只释放对应待确认项。10秒无ACK暂停发送并标AwaitingConsumer，30秒无ACK使stream过期、停止日志采集子进程并回收订阅；不自动重发未确认批次，不靠发送成功判断前端已消费。

停发期间继续接收的数据只进入同一有界Rust环形缓冲，超限覆盖旧项并累计drop；前端恢复时重新取得stream状态，过期则创建新stream读取受限最近日志，不承诺跨stream全量或恰好一次重放。详情/窗口关闭、显式stop、发送失败也回收；单窗口单实例一个活跃流。验证WebView完全不消费/不ACK时，IPC最多保留信用窗内数据且30秒回收，不只验证正常消费或关闭窗口。Channel仅提供传输顺序和效率，所有限流/信用/超时由应用实现，脱敏发生在任何排队/发送前。

发行矩阵增加原生自建镜像归档：MinIO/XXL/ES-IK ARM的已验证下载URL、归档SHA、image ID/平台与应用制品SHA一起记录；UI只在选择相关服务时展示下载/加载进度和缓存/离线状态。未产生这些制品之前对应发行行仍阻断，不能让新手先装Go/JDK/Maven，也不能把Docker模拟运行记成Apple Silicon原生支持。Docker认证首期以Desktop/Engine为主，其他被发现的运行时单独验证，不从“能发现路径”推断完整支持。

### 7.10 全局异常与消息（2026-11-13）

界面只挂载一个shadcn Radix Sonner 2.0.8 Toaster，位于页面与Dialog之外，沿用全局明暗主题与语义令牌。页面和业务组件不直接导入Sonner，不渲染局部Alert、FieldError、错误段落或“已复制/已导出”等结果文本；复制、导出、命令结果统一经feedback入口发布。字段使用data-invalid/aria-invalid标记，验证失败原因走全局消息；业务状态与体检资源数据使用Badge、列表等结构化展示。容量与删除授权仍由Dialog明确确认，风险和影响属于确认内容，不用局部警告条替代。

notifying-api集中覆盖类型化命令的拒绝与结果；workspace集中处理快照失联、环境问题和任务状态。单次命令失败不把正常连接标为失联；真正的快照失联禁用相关启动操作。同一持续故障只通知一次，恢复后清除旧消息并允许后续故障重新通知；任务提交和任务完成分别提示。API异常、React错误边界、未处理Promise与运行时异常使用统一映射，禁止把原始异常消息、堆栈、凭据、验证字段值或本机导出路径放入消息。

全局消息提供关闭与必要的恢复动作；严重连接故障保留到处理/关闭，常规结果自动消失，同类消息以稳定ID合并。日志仍保留原有批次上限、ACK和过期保护，仅将暂停/故障/空闲提示迁入全局。新增反馈从共享入口与错误映射维护，不能在各页面复制一套处理逻辑。
