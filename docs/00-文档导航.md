# 文档中心

> 当前工作箱仍处于设计阶段，尚无 `toolbox/` 实现。[一键启动设计完整性审查](research/04-一键启动工具箱设计完整性审查.md)（2026-11-12）发现资源隔离、配置联动、就绪判定等方面的待修订项；原有文档的“已对齐基线”不代表本轮审核通过或产品已可发布。请先阅读审查结论，再按 design → prd → plan 修订。

Code Ark 工作箱（Code Ark Toolbox）知识库参考 `business/lucky/docs` 的分层方式组织，遵循 **requirement → design → prd → plan** 的演进顺序，并将外部与源码盘点调研独立沉淀在 **research**。

文档来源链为 **design → prd → plan**：每一份 `design` 严格对应唯一一份 `prd`，每一份 `prd` 可拆分为一份或多份 `plan`；原始诉求与确认口径保留在 `requirement`，调研分析保留在 `research`（调研本身不自动成为技术合同，采纳后合入对应 `design`）。

| 入口 | 目录职责 | 说明 |
| --- | --- | --- |
| [原始需求](requirement/00-需求导航.md) | 需求来源与已确认决策 | 记录用户原话背景、确认结论 `Cxx` 与待定边界 `Qxx` |
| [技术设计](design/00-设计导航.md) | 顶层与领域技术合同 | 按底座蓝图 → 编排引擎 → 界面交互排序，遵循设计模板 |
| [需求与验收](prd/00-PRD导航.md) | 用户范围、故事与验收边界 | 每份 PRD 链接唯一来源 `design`，定义 `PRDxx-Rxx` 与 `US/TS` |
| [实施计划](plan/00-Plan导航.md) | 文件、接口、测试与验证步骤 | 每份 Plan 链接唯一来源 `prd`，拆解可执行步骤与验证命令 |
| [调研分析](research/00-调研导航.md) | 竞品拆解、版本实测、仓库盘点与设计审查 | 标注证据等级，与技术设计隔离维护 |
| [写作模板](templates/00-模板导航.md) | 设计 / 用户故事 / 测试场景模板 | 用于后续新增文档保持结构一致 |

## 维护规则

- 各目录独立连续编号并维护 `00-*导航.md`；文档内部链接使用相对 Markdown 路径。
- 变更技术规则先改 `design`，同步范围/验收至唯一 `prd`，再更新对应 `plan`；不跳过来源链直接修改下游文档。
- 现有 `*-start-local` / `*-start-lcoal` 服务配置与目录规范仍由根目录 [AGENTS.md](../AGENTS.md) 与 [CONTRIBUTING.md](../CONTRIBUTING.md) 约束。
