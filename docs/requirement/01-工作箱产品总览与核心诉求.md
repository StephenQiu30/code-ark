# 01 工作箱产品总览与核心诉求

来源：Code Ark 项目需求对话（2026-11-12）及仓库现状 [README.md](../../README.md)、[AGENTS.md](../../AGENTS.md)。

## 1. 原始痛点与产品愿景

- **核心问题（`REQ-01`）**：当前仓库中 Docker 服务分散在十余个独立目录中，需要用户一个一个手动进入目录配置 `.env`、准备数据卷或 SQL 后逐一启动，对日常使用者和刚刚接触编程的初学者门槛过高。
- **产品形态参考（`REQ-02`）**：参考 [`aiwentongxue/mac-gaming-toolbox`](https://github.com/aiwentongxue/mac-gaming-toolbox) 的“工作箱”形态，将分散操作整合为一个统一、可视化、带状态感知、场景预设与教程指引的桌面工作台。

## 2. 已确认的核心决策（Confirmed Decisions）

| 编号 | 确认事项 | 具体口径 | 来源依据 |
| --- | --- | --- | --- |
| `C01` | **跨平台覆盖** | 必须支持 **macOS + Windows + Linux** 三端，不采用仅限 macOS 的单平台原生方案 | 对话确认（方案 B） |
| `C02` | **技术底座选型** | 采用 **Tauri（Rust 后端 + Web 前端）**，使用当前最新稳定版系列（`tauri 2.12.5`） | 对话确认 + [调研 02](../research/02-Tauri最新稳定版本与跨平台技术选型调研.md) |
| `C03` | **纯独立开箱即用** | 下载安装工作箱后即可直接使用；**不要求用户安装 Git、不要求 clone 或绑定本地仓库** | 对话明确纠正（“我想要的是一个开箱即可用的工具箱”） |
| `C04` | **收拢范围** | 完整覆盖当前仓库全部 17 套 Docker Compose 服务，并将宿主机运行指南 `mediacrawler-start-local` 纳入工作箱教程指引 | [README.md](../../README.md) + [调研 03](../research/03-CodeArk现有17套服务痛点与兼容基线盘点.md) |
| `C05` | **非破坏性与数据安全** | 保留用户已有 `.env` 与持久化数据；不执行全局 `docker system prune`；不泄露明文凭据 | [AGENTS.md](../../AGENTS.md) |
| `C06` | **原有目录兼容性** | 根目录原有 `*-start-local` / `*-start-lcoal` 配置继续保留给习惯 CLI 的用户，工作箱在构建期复用现有模板而不破坏原目录 | [CONTRIBUTING.md](../../CONTRIBUTING.md) + [AGENTS.md](../../AGENTS.md) |
| `C07` | **知识库对齐** | 按 `requirement → design → prd → plan` + `research` + `templates` 组织项目文档，参考 `business/lucky/docs` 体系 | 对话确认 |

## 3. 明确排除的范围（Out of Scope for v1）

- **不内置虚拟化引擎**：不替代 Docker Desktop / OrbStack / Docker Engine 本身；用户机器仍需安装 Docker，但工作箱需主动检测、诊断并引导配置（例如 Elastic 需 >= 6 GB 内存）。
- **不做通用全能容器面板**：不对任意第三方 Dockerfile 或 Kubernetes 集群做通用管理。
- **不绑定生产部署能力**：不负责云端集群部署、TLS 证书签发或高可用编排。

## 5. 2026-11-12 审查后增量确认

前文保留需求形成时的历史记录。本节记录本轮明确指令及当前生效口径，具体技术取舍由对应design维护，不作为用户逐字段原话。

| 编号 | 确认事项 | 来源与边界 |
| --- | --- | --- |
| `C08` | 按完整性审查修订对应design、PRD和plan，支持真正一键启动与新手入门；本轮只改文档，完成后提交main并推送 | 用户本轮明确指令；不授权开始产品代码开发或将运行测试标为通过 |

- `REQ-05`：一键范围覆盖Docker就绪后的自动配置、依赖认证/初始化、真实连接、日常启停、配置应用及失败恢复。系统引擎安装仍按C03及既定非目标提供引导，不内置虚拟化。
- `REQ-06`：新手交付须有应用外安装/首次打开说明、轻量首个成功路径、实际连接与最小客户端示例；源码检查、真实服务和最终安装包分别验收，未执行不得写已支持。
- C02中的版本为2026-11-12选型时的锁定起点，实施须提交锁文件并验证兼容，不随“最新”字样自动升级。
- C01的三端目标保持，具体OS/CPU及Docker支持范围由发行合同逐项实测；C04仍要求全17套服务，不以构建成功或缩小未通过矩阵代替完整交付。
- C05的非破坏性扩展落实为实例资源归属、精确数据库权限及后端删除复核；外部连接授权不等于生命周期接管或整库删除许可。
- C06保护原CLI目录；工作箱从源码复用蓝图不等于沿用旧资源名，Nacos源码固定命名卷和其他未参数化项由独立实例覆盖层适配。

本轮合同在[设计导航](../design/00-设计导航.md)，13项审查的逐项承接在[文档中心](../00-文档导航.md)。所有代码/镜像/制品/运行验收仍待实施。

## 6. 目录收拢增量确认（2026-11-12）

| 编号 | 确认事项 | 来源与边界 |

| `C09` | 服务统一收拢到 `services/`，完整服务表集中在 `services/README.md`；首页与结构规范只保留索引入口 | 用户要求减少根目录与首页冗余；不授权开发桌面工作箱或启动环境 |
