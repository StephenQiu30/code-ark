# 02 服务依赖与新手使用场景清单

来源：基于 [README.md](../../README.md) 的场景入口与 [调研 03](../research/03-CodeArk现有17套服务痛点与兼容基线盘点.md) 整理。

> §1–§2保留早期需求基线；本轮审查后的当前执行口径见§3及对应design。不要据历史“安全替换”或固定卷名直接实现外部容器删除。

## 1. 面向编程新手的 7 大开箱场景（`REQ-03`）

刚接触编程的开发者通常只知道“我要跑一个什么项目”，不知道底层需要挑哪几个容器或先启哪一个。工作箱需直接提供以下可一键启停的场景组合：

| 场景 ID | 场景名称 | 包含服务 | 新手常见目标 |
| --- | --- | --- | --- |
| `backend-mysql` | 轻量后端开发（MySQL 栈） | `mysql` + `redis` + `minio` | Spring Boot / Node / Go 常见接口与文件上传联调 |
| `backend-pgsql` | 现代后端 / AI 应用底座 | `pgsql` + `redis` + `minio` | Python FastAPI / Next.js / AI Agent 数据底座 |
| `java-microservices` | Java 微服务标准套组 | `mysql` + `redis` + `nacos` + `sentinel` | Spring Cloud Alibaba 服务注册、配置中心与流控实验 |
| `java-distributed` | 分布式事务与任务调度 | `mysql` + `seata` + `xxjob` | 分布式事务与定时任务调度联调 |
| `workflow-temporal` | 持久化工作流引擎 | `pgsql` + `temporal` | Temporal SDK 工作流与 UI 调试 |
| `cdc-messaging` | MySQL 增量同步与事件流 | `mysql` + `canal` + `kafka`（支持切换 `rabbitmq`/`rocketmq`） | 数据变更订阅与异步事件流实验 |
| `search-observability` | 全文检索与可观测性 | `elastic` / `monitoring` | ES + IK 分词检索与 Prometheus/Grafana 监控看板 |

## 2. 必须自动化消除的新手卡点（`REQ-04`）

1. **零手改 `.env` 与密钥校验**：自动根据服务规则生成有效随机密钥/密码（如 Nacos Base64 Token、SearXNG 密钥、Canal <= 32 字符密码），并允许一键复制，无需理解每个环境变量格式。
2. **隐藏依赖链自动排序与初始化**：
   - 启动 `temporal` 自动先启动 `pgsql` 并等待健康、同步账号密码、初始化 Schema 与 `default` Namespace；
   - 启动 `canal` 自动先启动 `mysql` 并幂等创建复制账号及授权；
   - 启动 `xxjob` / `seata` 自动先启动 `mysql`、打通跨平台 Docker 内网连接并幂等建库建表；
   - 启动 `nacos` 自动确保 `nacos-start-local-data` 卷就绪；
   - 启动 `elastic` 自动用跨平台原生逻辑完成 6 GB 内存预检、磁盘预检、串行镜像构建与 License 续期，彻底摆脱 Bash `.sh` 依赖。
3. **本机已运行服务的和平共处**：若本机已有外部启动的同名容器（如 `nacos-standalone`）或端口被占用（如本机装了本地 MySQL 占着 `3306`），工作箱不得直接报错崩溃，应能识别外部容器并给出“仅观察 / 安全替换 / 改端口避让”的清晰选择。
4. **连接地址零误解**：明确告诉新手“本地代码（IDEA/VS Code）填 `127.0.0.1:端口`，容器内部填服务名或 `host.docker.internal`”，提供一键复制代码片段。

## 3. 审查后当前口径（2026-11-12）

本节承接`C08`与`REQ-05/06`，保留7场景和17服务范围，修订实现约束：

| 早期描述 | 当前合同 |
| --- | --- |
| Temporal先启动PG并同步凭据 | 优先复用已登记PG；无既有服务才创建一个托管PG。固定双库、同账号和版本/History约束保持；外部初始化须准确授权 |
| Nacos确保`nacos-start-local-data`就绪 | 源码实际是固定名称的非external卷；桌面使用实例专属卷，不直接挂入/删除旧卷 |
| 外部同名容器“安全替换” | 只读观察、显式连接授权或创建新托管实例；v1不自动停止/移除外部容器，不假装迁移旧数据 |
| Seata/XXL联动MySQL | 同一已认证绑定产生专属账号/库、实际网络/端口及完整JDBC；部分初始化可恢复，不独立生成错误密码 |
| CDC事件流场景 | 默认提供Canal订阅与所选队列的基础设施；Canal→队列桥接不是现有容器自动具备的业务能力，教程需单独标注运行示例 |
| 工作流/事务/调度场景 | 明确Temporal Worker、Seata业务undo_log/客户端、XXL执行器由应用提供；入门指南给可运行最小示例与结果 |
| 任意服务一键成功 | 全部必要job退出0、实际协议/后台连接验证后才为Ready；上游不可达/待业务接入/外部观察分别展示 |

`search-observability`须明确选择Elastic、Monitoring或两者；`cdc-messaging`默认Kafka，RabbitMQ/RocketMQ为明确替代选择，不默认同时启动全部。默认首次引导一个Redis，后续再扩展到所选项目组合。

新手允许在界面完成首次已有依赖授权、系统安装步骤与敏感删除确认；“一键”不意味着隐藏这些必要选择。Docker就绪并完成一次绑定配置后，启动不得要求手改.env、终端建库或手工导入SQL。失败需有复检、重试、取消、保留数据恢复出口。
