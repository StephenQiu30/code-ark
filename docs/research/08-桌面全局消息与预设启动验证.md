# 桌面全局消息与预设启动验证

日期：2026-11-13。范围：本机 macOS ARM64 源码预览及本地 Docker Desktop；不代表其他平台或最终安装包验收。

## 原生桌面

- 通过真实 WKWebView 点击检测按钮，立即出现持续的全局 Sonner「正在检测 Docker 连接…」，按钮禁用；实际后端确认后替换为「Docker 连接已确认」。重复手动操作使用独立消息，快照故障继续按事件去重。
- 服务目录复用统一启动组件；预检、授权及启动任务的反馈由唯一全局入口发布。绑定授权后继续原启动；关闭弹窗后的晚到结果不会自动启动。
- 本机已有宿主 Redis 占用 6379，实际预检通过全局消息报告 PortConflict，没有停止现有进程。将工作箱 Redis 改为 16379，保存验证、单次未知容量确认并应用；真实实例达到 Ready，连接页显示 127.0.0.1:16379 和测试通过。另行 RESP PING 返回 PONG，实例保留运行供用户查看。
- 最后一轮退出旧进程并重启原生预览，真实点击再次观察到检测loading→成功；按保存配置点击Redis启动，经单次未知容量确认后达到已就绪、连接测试已通过，另行16379的RESP PING再次返回PONG。当前预览保持打开、Redis保持运行。
- 此路径发现并修复：未应用实例不应请求 connectionView；首次配置的 null appliedGeneration 应与后端 unapplied 基础版本一致；端口字段展示可读名称，避免暴露内部字段和代际标识。

## 真实编排验证方法

使用 `examples/prepare_acceptance.rs` 生成专用工作区与控制目录，显式固定 CLI、context、daemon、run ID 及 27000–27999 端口。`examples/preset_startup.rs` 运行同一 Engine.start，等待所有必要协议探针，再通过 Engine.stop 保留数据停止，重复启动复验。只处理该隔离工作区中核验归属的资源，未启停其他项目或宿主 Redis。

首次隔离 MySQL 验证揭示 readiness 对授权库名 `test\_db` 的误判：MySQL 已健康、业务认证及 binlog 查询成功，SHOW GRANTS 的字面库名转义未被接受。权限匹配现统一到 bindings，readiness 和 Canal 共同使用，并覆盖错误库、错误权限、表级权限和部分 REVOKE 的拒绝测试。初次失败不能计为通过，修复后重新运行。

## 本轮实际问题与修复

- SQL客户端的自动删除与归属清理竞争可能覆盖已成功查询的结果。现由持有专用锁的归属清理统一删除，失败保留可恢复记录；真实查询失败不被清理错误掩盖。Temporal最终两轮启动与后台复验均通过。
- Canal 采用独立 `codeark_probe` destination、多实例模式及从授权数据库派生的黑名单，跳过非授权库的元数据读取；不授予系统库额外SELECT。白/黑名单使用 `[.]` 避免Properties多层转义。
- 一次Canal预检得到 `UnknownMemory`，原始失败采样未保留，不能断言具体原因。现只对未知样本最多重新采样3次，每次重新核验目标，持续未知仍拒绝，不当作0或可用内存。
- 三类Java检测的真实 `ProbeClientLaunchFailed` 已用零输入、同JRE/同资源参数的对照定位：Mac可读的原随包目录对Docker挂载不可见，复制到稳定路径后可启动；没有OOM证据。运行时现将经过白名单/SHA校验的文件复制到当前control的不可变内容摘要目录，再校验、只读挂载；原资源仍是唯一来源。
- 启动Ready后强制后台观察暴露Go模板直接访问缺失的HostConfig.Mounts/State.Health导致失败。现使用安全index/with保留null语义，原生Docker模板实测通过；Canal、Temporal最终两轮新鲜观察通过。旧的依赖统一阻断已移除，观察期限按声明探针预算计算，保留单任务执行、并发上限与节流。

RocketMQ的Proxy探针原先请求系统Topic `TBW102`，真实SDK返回40002/ILLEGAL_TOPIC，安全分类为SystemTopicForbidden。官方[5.5校验实现](https://raw.githubusercontent.com/apache/rocketmq/rocketmq-all-5.5.0/proxy/src/main/java/org/apache/rocketmq/proxy/grpc/v2/common/GrpcValidator.java)明确禁止此请求。新探针通过锁定SDK的公开接口，等待[服务端settings应答及心跳OK](https://raw.githubusercontent.com/apache/rocketmq/rocketmq-all-5.5.0/proxy/src/main/java/org/apache/rocketmq/proxy/grpc/v2/client/ClientActivity.java)，保留独立的Broker路由验证；不以空Topic的客户端对象非null代替网络协议成功。最终两轮均取得startup Ready、清启动证据后的LIVE_PASS及Engine.stop，原12秒探针预算保持不变；精确会话终止成功。完整证据见09。

协议客户端的最小失败摘要仅含固定码、退出码和OOM布尔；137本身不作为OOM证据，不保留标准输入/输出、密码、Token或原始inspect。
