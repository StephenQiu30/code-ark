核查日期：2026-11-12（Asia/Shanghai）。基线：`a9acabc`。范围：桌面、前端、Rust核心、配置/类型、Docker、探针SDK、17服务镜像和跨平台发行。**仅调研与文档；没有安装依赖、编译产品/镜像、拉取镜像层、启动容器或修改现有Compose。**

## 1. 结论与采用范围

保留Tauri2 + React + Rust + Docker Compose的方向。需要补齐的不是另一个服务管理后台，而是明确的依赖组合、端点/类型协议和可获取的原生制品。

| 决策 | 本次取舍 | 原因及代价 |
| --- | --- | --- |
| 桌面 | 保留Tauri2；不切换Electron/SwiftUI/Wails | 复用既定Rust运行核心与Web界面；接受三种WebView、Rust/TS双栈和原生构建矩阵 |
| 前端 | React19、Vite8、Tailwind4、shadcn Base UI | 同一组件底座，保留简单双栏；必须验证实际WebView的CSS能力，不能只测浏览器 |
| 类型 | Rust DTO派生ts-rs，导出TS并做serde夹具回归 | 不引入预览版跨语言框架；生成类型不替代后端权限或运行时校验 |
| 核心 | Tokio、SQLx、Reqwest/rustls；JSON持久状态与标准库文件锁 | 避免再部署业务数据库、服务端HTTP框架或另一套Docker SDK；保留既定可恢复文件协议 |
| 配置 | Node `yaml`负责构建期核验；Rust `serde-saphyr`生成受控覆盖层 | 不新用已停止维护的serde_yaml；Compose最终模型仍是合并语义权威 |
| 事件/日志 | 低频状态事件 + 快照；日志用Tauri Channel、限流/有界缓冲 | 官方明确事件不面向高吞吐；Channel本身不能代替应用层内存上限 |
| 密钥/锁 | getrandom系统随机源；Rust标准库File锁 | 避开不同rand主版本OsRng接口差异，不再为已有标准能力加fs2/fs4 |
| 探针 | 原生HTTP/SQL + 按协议隔离的一次性Java客户端 | 不要求用户安装JDK/Maven；不把所有协议SDK塞入同一个冲突classloader |
| 服务UI | 桌面适配选Kafbat1.5.0、Apache Dashboard2.1.0 | 保留Kafka/Rocket功能与数据，替换旧UI制品；CLI原模板不变，API/资源差异需实测 |
| 特殊制品 | MinIO源码构建、XXL3.5.0重打包、ES/IK原生构建，由维护者提供受校验归档 | 解决入口/ARM/用户端构建缺口；没有可用产物不放行完整发行，不回退模拟或隐式build |

不因“最新”批量升级现有MySQL/PG/Redis/Seata等核心服务，也不替换为其他产品。旧数据格式、客户端/Schema兼容和许可证信息仍按实际版本核验。v1继续不支持远端Docker、本机原生数据库自动绑定及已初始化数据库账号密码轮换。

### WebView是额外门禁

Tailwind4官方最低浏览器为Chrome111、Safari16.4、Firefox128；不能从“操作系统能装Tauri”直接推得CSS正常。[兼容要求](https://tailwindcss.com/docs/compatibility)。候选生产JS target显式覆盖所支持WebView（macOS14的Safari17能力为起点，Windows使用已验证WebView2），不使用Vite开发期esnext作为发行兼容证明；CSS另做oklch/color-mix/自定义属性等所用能力检查和原生截图/交互回归。

SQLx0.9启用MySQL、Tokio及TLS时应按该版本注册特性精确设置；现有公开README某些例子仍写0.8，不能照抄。仅声明的本地容器认证范围内才启用无TLS的mysql-rsa兼容，默认不借此放宽外部拓扑。[官方SQLx](https://github.com/launchbadge/sqlx/tree/v0.9.0)、[0.9元数据](https://crates.io/api/v1/crates/sqlx/0.9.0)。Reqwest0.13特性另见[注册元数据](https://crates.io/api/v1/crates/reqwest/0.13.5)。

serde_yaml原仓库已于2024-03归档，注册版本也标deprecated，不选为新默认；serde_yaml_ng保留作对照，不只因“fork可下载”判其为唯一可选。选择serde-saphyr基于已发布版本、受控tag和预算能力，仍要用真实Compose验证输出。[原库状态](https://github.com/dtolnay/serde-yaml)、[serde-saphyr文档](https://docs.rs/serde-saphyr/2.1.1/serde_saphyr/)。标准文件锁行为见[Rust File](https://doc.rust-lang.org/std/fs/struct.File.html)。

### 日志传输

StepProgressEvent保持低频+seq/快照；日志使用Channel<LogBatch>与应用层ACK。前后端每流2000行/2MiB、单行序列化后16KiB、完整batch100行/64KiB、10批/秒；最多2个未确认batch/128KiB，前端渲染提交后才ACK，重复/未知ACK不加credit。到限不再发送，10秒无ACK停发、30秒过期回收；新数据只进有界环形缓冲、溢出计数可见。恢复只读取受限最近日志，不承诺全量重放；关闭/异常/发送失败均回收，先脱敏再入队。

这些是应用层限制，不声称Channel内建背压/持久重放；验证包含WebView完全不消费但发送仍成功，防止只限已显示行而IPC无限积压。官方说明事件不适合高吞吐，Channel为流式优化：[Tauri调用前端](https://v2.tauri.app/develop/calling-frontend/)。

## 4. Docker运行时与制品分发

- v1认证基线优先Docker Desktop（macOS/Windows）和Docker Engine（Linux），用户选择本地Linux containers；不内置或再分发Docker引擎。OrbStack/Rancher可被发现不等于已认证，新增运行时要加独立实测行。
- 保留Compose CLI，最低能力2.24.4；本机只读查询为Docker CLI29.9.3/Compose5.7.0，不要求所有用户恰好同一版本，也不凭主版本=2来拒绝更新版。Engine/CLI API协商和实际运行时组合另测。
- 不默认使用Bollard重写Compose编排，也不依赖Docker Socket从前端直接调用。stdout/stderr分离，解析官方JSON字段；人工表格文本不能作稳定协议。
- macOS实际支持由Docker当前和前两代OS政策、选定运行时版本与Tauri/WebView交集决定；“macOS14+”只是候选起点，不是永久支持公告。[Docker要求](https://docs.docker.com/desktop/setup/install/mac-install/)。

### 原生自建制品的完整路线

MinIO、XXL ARM和ES/IK不让新手在本机安装Go/Maven编译。维护者先在原生Linux amd64/arm64构建/重打包同一上游版本，验证后可提供版本发行附件中的**Docker image save归档**：

1. 源码锁到明确commit，builder/JRE/系统包及SDK锁定，保存源归档校验和、构建命令和上游LICENSE/NOTICE；本轮未构建或再分发。
2. 按架构生成镜像，记录image ID/config digest及平台，导出image-save归档并计算归档SHA-256；不能只写一个“OCI文件”就假定所有Docker存储后端都可load。
3. `ImageArtifactRef`区分`registry`和`release-image-archive`。前者锁registry manifest digest；后者锁允许来源的HTTPS发行URL、归档SHA、预期image ID、架构和唯一内容标签。
4. 工作箱先验证下载内容，在固定目标`docker image load`，随后inspect ID/架构和实际运行容器Image；override用唯一内容标签、pull_policy=never。缓存按内容寻址复用，普通停止/重置不得清理全局镜像。
5. 候选镜像/归档没有生成前，相关行保持待构建并阻断公开release；不能填写臆造digest、自动降级到AMD64模拟，也不能把维护者本地缓存当新用户可获取制品。

归档不是已经存在的下载能力；实际附件URL、哈希、签名及可获取性在后续发行任务中形成。安装包不塞入全部镜像，按所选服务下载并显示体积/进度/空间要求；断网且未缓存时明确失败/重试。

### 三个必须改变的制品来源

1. **MinIO**：官方README现提供源码安装/构建路线，并说明历史预编译二进制不再更新。本次匿名manifest请求在Docker Hub及Quay均失败，不能认定全网不可用，也不能继续把latest当发行保证。候选锁源码`RELEASE.2025-10-15T17-29-55Z`，公开Git引用为`9e49d5e7a648f00e26f2246f4dc28e6b07f8c84a`；其go.mod为go1.24.0/toolchain1.24.8，生产构建候选使用仍受维护的Go1.27.4，禁用自动拉旧toolchain并验证构建，失败需重新评估，不悄悄回退。源码版本后续升级需独立验证，当前不声称此旧源码与新编译器已经通过。[官方源码说明](https://github.com/minio/minio)、[固定go.mod](https://raw.githubusercontent.com/minio/minio/RELEASE.2025-10-15T17-29-55Z/go.mod)、[Go发行索引](https://go.dev/dl/?mode=json)。
