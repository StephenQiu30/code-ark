# 一键启动工具箱设计完整性审查

核查日期：2026-11-12（Asia/Shanghai）。审查基线：`main` 的 `fa012c9`。状态：**审查意见，待修订设计及下游验收；不代表实现或运行验收通过**。

## 1. 结论与范围

**当前设计方向可行，但尚不能完整支撑“真正一键启动、环境操作友好、新手开箱入门”的交付承诺。** 内嵌蓝图、独立工作区、依赖 DAG、可视化配置、场景入口与连接指引均值得保留；需要先补齐资源归属、配置联动、就绪判断及安装包验收，再按现有三条主链实施。

本轮读取 `docs/` 原有 25 份文档，对照 17 套 Compose、相关公开 `.env.example`、初始化 SQL、配置及脚本核验。仓库当前不存在 `toolbox/`，三份 Plan 的实施与测试仍为未执行。本轮仅做文档审查和只读配置验证，没有启动、停止、删除容器，也没有运行数据库初始化或重置。

“一键启动”的建议验收口径：

- Docker 尚未安装或未启动时，提供分平台安装、启动和复检入口；不承诺由工作箱内置虚拟化引擎。
- Docker 就绪后，用户选择场景并点击启动，无需 Git、终端、手工编辑 `.env` 或导入 SQL，即可到达**真实可连接**状态。
- 冷启动拉取镜像或构建耗时可见，失败能够定位和重试；已有配置、数据及外部环境得到保护。
- 停止、再次启动、应用重开、升级与修改配置后的行为明确；新手能够复制正确地址与凭据，完成最小客户端验证。

以下均为审查建议，不新增“用户已确认”决策。P1 表示应在据此实现相关核心行为前修订，P2 表示应在宣称面向新手公开交付前补齐。

## 2. P1：需要先修订的合同

### ARK-01：相同 Compose 项目名与固定卷名破坏工作区隔离

**定位**：[设计 01 §7.5](../design/01-CodeArk工作箱顶层架构与蓝图同步设计.md) 第 86 行；[设计 02 §7.2、§7.4](../design/02-跨平台Docker探测与自动化编排设计.md) 第 54–58、75–78 行；[Plan 03 任务 4](../plan/03-工作箱前端工作台与跨平台CI实施计划.md) 第 71 行。

**证据与触发**：工作箱被要求沿用旧项目名、容器名和网络名，但所有权仅按容器工作目录判断。临时目录并不改变 Docker 项目名、固定 `container_name` 或卷名。[Nacos Compose](../../nacos-start-local/docker-compose.yml) 第 39–41 行只有 `name: nacos-start-local-data`，**没有 `external: true`**，与当前盘点及 README 的“外部卷”描述不符。Compose 的 `name` 卷名不受项目名前缀隔离，详见 [官方卷规范](https://docs.docker.com/reference/compose-file/volumes/)。

**影响**：只读观察旧容器并不能保护同名网络和命名卷；新托管实例可能挂入旧卷，`down -v` 重置有删除既有卷的风险。计划中的临时目录 E2E 同样可能与用户本机资源碰撞。

**修订建议**：区分“源码兼容标识”与“运行实例标识”。托管实例为项目、容器、网络、命名卷统一生成工作区唯一名称，并在覆盖层同步所有外部网络引用及内部主机名；固定 `name:` 卷也必须处理。资源归属同时记录工作区 ID、实例 ID、Docker 目标、资源 ID 与真实挂载路径，危险操作逐项核验。若仍选择共用旧资源，应显式登记为外部资源并禁止自动删除。测试使用独立 Docker 目标或完整隔离命名，不能只换目录。

**验收出口**：旧 CLI 实例、另一工作区、临时测试实例同时存在时，启动/停止/重置一方不改变其他实例容器、卷内容及网络连接。

### ARK-02：XXL-Job 的 MySQL 网络覆盖不会改变实际 JDBC 地址

**定位**：[设计 01 §7.5](../design/01-CodeArk工作箱顶层架构与蓝图同步设计.md) 第 89 行；[PRD 01 TS-03](../prd/01-CodeArk工作箱底座与蓝图管理PRD.md)；[Plan 01 任务 4](../plan/01-服务清单与蓝图同步实施计划.md)。

**证据与触发**：[XXL-Job Compose](../../xxjob-start-local/docker-compose.yml) 第 16–21 行将 JDBC URL 和凭据拼入 `PARAMS`。本轮用公开样例生成临时 override，只注入设计要求的 `MYSQL_HOST=mysql`、`MYSQL_PORT=3306`，合并结果为：

```text
docker compose config --quiet: exit 0
容器环境 MYSQL_HOST: mysql
PARAMS 中 JDBC 目标: host.docker.internal:3306
```

Compose 对每个文件先插值再合并，后追加容器环境变量不会重新计算已经展开的字符串，详见 [官方插值规则](https://docs.docker.com/reference/compose-file/interpolation/)。因此现有 YAML 字段断言即使通过，Linux 实际连接仍可能失败。

**修订建议**：在生成最终配置前确定全部联动变量，使用明确的插值输入，或完整覆盖 `PARAMS`；规范子进程环境变量优先级，防止宿主机同名变量覆盖工作箱配置。把断言目标改为**最终展开配置中的 JDBC 地址、账号、库名**，并补实际认证联调。Seata 自定义外部端口还需处理挂载配置中硬编码的 `:3306`。

**验收出口**：MySQL 宿主机端口改为非默认端口后，XXL-Job/Seata 仍走内网容器端口成功认证；Linux 不依赖宿主机回环端口转发。

### ARK-03：MySQL 凭据联动与中断后的初始化缺少完整定义

**定位**：[设计 01 §7.4](../design/01-CodeArk工作箱顶层架构与蓝图同步设计.md)；[设计 02 §7.3](../design/02-跨平台Docker探测与自动化编排设计.md) 第 66–69 行。

**证据与触发**：Temporal 明确同步 PG 账号，但 Seata/XXL-Job 的样例为 `MYSQL_USERNAME=root`、`MYSQL_PASSWORD=your_mysql_password`。按逐服务随机补值规则，会生成与 MySQL 实际 root 密码无关联的值；没有规定改为专属账号的创建授权流程。Canal 的 `CREATE USER IF NOT EXISTS` 也不会自动让旧账号密码与新生成值一致。

此外，[XXL-Job SQL](../../xxjob-start-local/tables_xxl_job.sql) 包含普通 `CREATE TABLE` 与固定主键 `INSERT`。初始化在建成部分表后中断，再按“缺少核心表就重新导入整份 SQL”执行，会遇到已有表或重复记录；仅验证第一次成功、再正常重启不足以覆盖此问题。

**修订建议**：明确依赖账号的单一凭据来源，优先采用服务专属数据库与账号；定义已存在账号的认证校验和失配处理，不擅自修改外部账号。为 SQL 初始化记录版本及完成状态，区分空库、部分初始化、兼容已初始化、旧版不兼容；中断恢复不能重放破坏性语句或重复种子数据。DDL 不能被笼统视为可整体事务回滚。

**验收出口**：全新链路无需手填密码即可成功；在每个初始化步骤故意中断后重试，最终可用且保留已存在的用户记录；旧凭据不匹配时清楚报错。

### ARK-04：按配置库名重置，不足以证明数据库归属

**定位**：[设计 02 §7.2、§7.4](../design/02-跨平台Docker探测与自动化编排设计.md) 第 57、77 行；[PRD 02 US-07、TS-08](../prd/02-跨平台环境预检与服务自动化编排PRD.md)。

**证据与触发**：设计允许手填外部库，也允许自定义 `${MYSQL_DATABASE}`，随后重置直接对配置库执行 `DROP DATABASE`。输入服务名确认不能证明这个库属于当前实例。例如用户把库名填成既有业务库，或让两个服务共用一个库，现有规则仍可能把整库当“专属库”删除。

**修订建议**：记录由工作箱创建的数据库、账号、所属实例及服务器身份；重置前与当前连接重新核对。手填外部数据库默认禁用整库删除；即使托管库也需验证独占性、保留数据库名限制和下游影响，不能仅信任表单值。独立数据目录清理同样应校验规范化路径、软链接及工作区边界。

**验收出口**：配置指向外部库、系统库、另一实例库或多个服务共用库时，拒绝整库重置；归属明确的专属库可重置且不影响其他业务数据。

### ARK-05：`!override` 的最低 Compose 版本写错

**定位**：[设计 01 §7.5](../design/01-CodeArk工作箱顶层架构与蓝图同步设计.md) 第 88 行；[PRD 01 §7.5](../prd/01-CodeArk工作箱底座与蓝图管理PRD.md)；[Plan 01 全局约束](../plan/01-服务清单与蓝图同步实施计划.md)。

**证据与触发**：三处写 Compose `v2.20+` 支持 `ports: !override`，而 [Docker 官方合并规范](https://docs.docker.com/reference/compose-file/merge/#replace-value) 明确最低为 **2.24.4**。按原预检放行 2.20–2.24.3，会在真正改端口时解析失败。

**修订建议**：将最低要求统一为 `>= 2.24.4`，预检解析真实版本并做能力验证；本机已是 Compose v5，不能按“主版本必须等于 2”判断。生成配置后先执行 `config --quiet` 再运行，错误输出脱敏。

**验收出口**：2.20、2.24.3 被明确拦截，2.24.4 和兼容的更新版本可生成并正确替换端口；不能因不使用标签而意外保留旧发布端口。

### ARK-06：RocketMQ 的默认宿主机模式会破坏容器侧 Broker 访问

**定位**：[设计 01 §7.5](../design/01-CodeArk工作箱顶层架构与蓝图同步设计.md) 第 90 行；[PRD 01 TS-03](../prd/01-CodeArk工作箱底座与蓝图管理PRD.md)。

**证据与触发**：设计将 Broker 注册地址设成 `127.0.0.1`，但 [RocketMQ Compose](../../rocketmq-start-local/docker-compose.yml) 中 Console 位于单独容器。Console 或其他容器客户端从 NameServer 获得该路由后，回环地址指向自己；修改端口映射不能修复这个地址。当前测试仅检查生成文件，不验证路由可达性。

**修订建议**：明确宿主机、Console、业务容器三种访问者的路由策略。可选择经验证的共同可达地址或代理方案，但不能把仅适用于宿主机的回环地址作为所有访问者的默认广播地址；如暂时存在限制，应在 UI 明示并调整默认模式。

**验收出口**：宿主机实际发送/消费消息，Console 实际查询 Broker/Topic，容器客户端按承诺的支持范围收发消息；三端验证且端口改绑后仍成立。此项本轮为配置与网络语义分析，尚未做运行复现。

### ARK-07：缺少 17 套服务统一且可执行的就绪合同

**定位**：[设计 02 §7.3](../design/02-跨平台Docker探测与自动化编排设计.md) 第 62–63 行；[设计 03 §7.2](../design/03-工作箱界面交互与新手引导设计.md)；[Plan 03 任务 4](../plan/03-工作箱前端工作台与跨平台CI实施计划.md)。

**证据与触发**：管线统一写 `Compose Up & Wait Healthy`，但 MinIO、Nacos、Sentinel、Seata、XXL-Job、SearXNG、RocketMQ 的常驻服务，以及 Kafka UI/Grafana 没有健康检查。等待 `Health.Status == healthy` 无法统一完成；若以 `running` 或首页 200 代替，又无法证明后台连通。Temporal/Elastic 的一次性任务则应以成功退出判定，不能当常驻容器等待健康。

**修订建议**：catalog 为每个组件定义常驻/一次性类型、探针、成功标准、超时、重试策略和必要初始化退出码；服务状态区分运行、就绪、失败、降级、等待人工处理。业务探针从后端执行，不能依赖镜像里一定有 `curl`。

**验收出口**：按 §5 的全量矩阵验证；错误凭据、数据库不可达或初始化失败时，前端不能显示“健康运行”。

### ARK-08：未固定 Docker 目标，宿主机预检可能与实际执行位置不一致

**定位**：[设计 02 §7.1–§7.2](../design/02-跨平台Docker探测与自动化编排设计.md) 第 44–55 行；[设计 03 设置页](../design/03-工作箱界面交互与新手引导设计.md)。

**证据与触发**：只找 CLI 路径并调用 `docker info`，没有规定 context/endpoint。Docker 当前 context 或 `DOCKER_HOST`、`DOCKER_CONTEXT` 可以指向远端，详见 [Docker 官方 Context 说明](https://docs.docker.com/engine/manage-resources/contexts/)。此时工作箱检查本机端口和本机工作区，容器却在别处执行，挂载路径、地址、资源归属及重置范围全部失配。

**修订建议**：每次运行绑定明确的受支持本地运行时/context，统一传给所有 Docker 命令，并记录 daemon 身份；识别并阻止不支持的远端目标及 Windows containers 模式，不擅自切换用户全局 context。操作中目标变化应中止。环境体检区分 Docker 未安装、未启动、Compose 过旧、权限不足和目标不支持。

**验收出口**：当前 context 为远端、环境变量覆盖目标或中途切换 daemon 时，禁止按本地假设执行；正常本地目标下预检与实际挂载、端口及资源清单一致。

## 3. P2：面向新手交付前必须补齐的路径

### ARK-09：外部替换、修改配置和中断恢复缺少完整生命周期

**定位**：[设计 01 §7.3–§7.4](../design/01-CodeArk工作箱顶层架构与蓝图同步设计.md)；[设计 02 §7.2–§7.3](../design/02-跨平台Docker探测与自动化编排设计.md)；[设计 03 §7.2](../design/03-工作箱界面交互与新手引导设计.md)。

删除旧容器后从新工作区启动 MySQL/PG，虽然旧绑定数据仍在磁盘上，新实例可能显示空库；现在的“接管”命名没有把“保留旧文件”与“继续使用旧数据”区分清楚，也没有新实例启动失败时的恢复步骤。切换工作区同样未规定原服务与数据如何处理。

建议把“观察既有实例”“创建全新托管实例”“显式迁移数据”分开；后两者先说明数据来源和旧服务恢复方案。配置编辑增加“保存草稿 → 校验 → 应用/重建 → 连接验证”的状态，数据库密码不能只改 `.env` 当作已轮换。为拉取、构建、健康等待设置超时和取消边界；定义部分成功保留策略、可重试步骤、应用重开后的状态重建，以及跨进程单实例或工作区锁。蓝图更新遇手改文件默认等待处理，不能仅备份就宣称升级无损。

验收应覆盖删除旧容器后启动失败、DDL 中途退出、应用关闭重开、两次打开应用、配置应用失败、工作区移动及保留数据重建。

### ARK-10：冷启动引导与场景教学尚未到“代码跑通”

**定位**：[需求 02 场景清单](../requirement/02-服务依赖与新手使用场景清单.md)；[设计 03 §5–§7](../design/03-工作箱界面交互与新手引导设计.md)。

需要补全无 Docker 用户的分平台入口、Windows WSL2/虚拟化前提、支持的 Linux 发行版与运行库，以及“完成后重新检测”。安装包无法打开的解决步骤必须在下载页/发行说明可见，不能只放在尚未能打开的应用内。首次拉取的网络失败、代理、磁盘不足也需要明确操作出口，不能用“1 分钟内从安装到代码连库”的未实测承诺代替。

场景应明确提供哪些基础设施、哪些仍由应用提供：Temporal Worker、XXL-Job 执行器、Seata 客户端及业务表 `undo_log`、Canal 事件消费/转发等。当前 Canal 配置没有把事件自动投递到 Kafka 的完整链路，容器同时启动不能作为 CDC 到消息队列成功的证明。建议默认引导一个轻量组合，完成连接测试再推荐扩展场景，并提供可复制的最小客户端示例及成功输出。

### ARK-11：版本、架构、磁盘与密钥默认值仍有可复现性缺口

**定位**：[设计 01 §7.3–§7.4](../design/01-CodeArk工作箱顶层架构与蓝图同步设计.md)；[调研 03](03-CodeArk现有17套服务痛点与兼容基线盘点.md)；[Plan 01](../plan/01-服务清单与蓝图同步实施计划.md)。

MinIO 和 RocketMQ Console 仍使用 `latest`；三端桌面包可编译不代表所有镜像都支持目标 CPU。建议为发行蓝图记录实际镜像版本/digest、架构与验证状态，并检查 Elastic/IK 构建下载源；未验证的平台不得显示为已支持。工作区剩余空间不能替代 Docker 镜像/命名卷所在 daemon 数据盘的空间检查；Linux bind mount 权限也需覆盖。

`~/.code-ark` 并不保证整个路径无空格或中文，用户名与用户自定义路径均可能包含这些字符，应使用路径参数、真实测试而非路径假设。工作区中的 `.env` 使用限制性权限/ACL，原子保存且不覆盖已有有效凭据。

当前仓库尚无 `.gitattributes`，应按根协作规范补充容器 Shell 脚本的 LF 检出约束；构建期强制 LF 也应保留，并加入 Windows 实际检出与物化验证。

密钥生成不能只靠通用占位前缀：Nacos 样例是公开且格式合法的固定 Token，Kibana 样例为 `change-this-...`，均不匹配当前清单。应为首次托管实例逐字段声明生成策略，并区分“公开样例值”与“用户已有值”；已初始化实例禁止悄悄改密码。诊断包优先使用字段白名单，补 URL 编码等密钥表示及日志中的未知敏感信息处理和导出预览；仅替换已知 `.env` 原值不应承诺任意日志“100% 脱敏”。

### ARK-12：三端打包计划不足以证明新手安装包可用

**定位**：[Plan 03 任务 4 与完成判据](../plan/03-工作箱前端工作台与跨平台CI实施计划.md) 第 64–78 行；[PRD 03 TS-13](../prd/03-工作箱可视化工作台与新手引导PRD.md)。
