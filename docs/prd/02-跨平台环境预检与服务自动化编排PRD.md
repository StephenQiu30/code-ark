# 02 跨平台环境预检与服务自动化编排 PRD

唯一来源 design：[02 跨平台Docker探测与自动化编排设计](../design/02-跨平台Docker探测与自动化编排设计.md)。状态：**2026-11-12审查修订已纳入合同，全部实现与运行验收未执行**。只承接此design，技术协议沿来源读取；实施见[Plan 02](../plan/02-跨平台Docker探测与编排引擎实施计划.md)。

## 1. 摘要

在所选本地Docker目标上，用户一次启动动作完成依赖解析、授权范围内初始化、镜像准备、部署和业务探针。可复用已有基础数据库，能在中断后恢复；停止、重建和重置不会误操作外部实例、其他工作区或无关业务库。

## 2. 责任与确认

来源为`C01/C04/C05/C08`、`REQ-03/04/05/06`及`ARK-01/03/04/07/08/09/10/11/12`。后端实现者负责权威状态和所有权复核，前端消费结构化结果，验收人员记录实际目标和故障注入结果。用户本轮只授权文档修订。

## 3. 背景与范围

原服务包含无healthcheck的组件和需退出0的一次性任务，不能统一等待healthy或只检查首页。数据库部分DDL、账号失配、远端context、固定资源名、内存锁和库名驱动的DROP都有明确反例。停止外部容器后接管的旧方案废止，改为观察/连接/显式创建新托管实例。

v1已有数据库自动绑定仅支持同一已固定本地Docker daemon内的MySQL/PG容器；未发布宿主机端口可通过锁定一次性网络客户端认证，无需用户开放端口。本机原生/远端数据库和不可核验拓扑显示明确不支持，不偷偷新建替代实例。v1不提供已初始化数据库账号密码轮换，只允许验证并更新已生效连接凭据。

## 4. 目标与成功标准

- Docker缺失、未启动、权限、版本、目标、架构及容量问题在动作前分开提示。
- 对已有依赖优先复用，凭据来源一致；Schema/种子中断后安全续跑。
- 服务Ready满足全部必要job和协议/API条件；降级或等待客户端准确显示。
- 连点、多进程、应用重开、取消和超时均有持久可恢复状态；不自动降级数据库。
- 删除前有准确计划及后端复核，外部库和未知业务数据不得被整库/整实例重置。

## 5. 使用者与场景

### US-04 · 跨平台环境预检

作为用户，希望无需手配PATH就知道Docker为何不能用，并在修复后复检。

- 来源：design §7.1–7.2；R01/R02。
- 正常：显示实际目标、版本、内存、两类磁盘空间、端口与架构；未通过门禁不调度容器。
- 边界：GUI PATH、Windows无窗、Linux权限、UDP占用、远端context、兼容新Compose主版本。
- 异常：未知容量不能伪报足够，实际端口竞争转成可操作冲突；不后台提权或切全局context。
- 追踪：TS-05/16；Plan02任务1–2。

### US-05 · 和平复用已有服务

作为已有MySQL/PG的用户，希望选择一次连接与初始化授权后复用它，不必删除旧容器或多启一套。

- 来源：design §7.3/7.8；R03/R09。
- 正常：ExternalObserve只观察；显式ExternalConnected验证服务器和权限，初始化只作用于已列名专属资源。
- 边界：相同名称/路径不能认领；现有pgSQL网络与凭据登记后供Temporal复用；外部服务不能启停/删卷/整库重置。
- 异常：拒绝未授权DDL、失配账号或来源不明Schema；创建新实例明确提示旧数据不自动迁移。
- 追踪：TS-06/19；Plan02任务3。

### US-06 · 全链路初始化与真实就绪

作为用户，希望一次动作启动所需基础设施，实际连接通过才看到成功，重复操作保留数据。

- 来源：design §7.4–7.6；R04/R05/R07/R09。
- 正常：动态DAG去重，认证后的专属凭据同步；逐步骤建表/种子可恢复，Temporal双job退出0、Namespace保留设置。
- 边界：外部库无自动授权、半初始化、自定义库名、旧账号、无healthcheck组件、网络上游失败。
- 异常：失败停止后续步骤并保留成功依赖；不重放SQL覆盖用户数据、不用随机新值“修复”已有数据库密码。
- 追踪：TS-07/17/19；Plan02任务4–5。

### US-07 · 分级停止与准确重置

作为用户，希望停止场景时不影响其他项目，重置某服务只清自己的资源。

- 来源：design §7.8；R06。
- 正常：展示依赖/场景影响；ResetPlan逐项列资源ID、库/卷/路径，后端复核后只删自有独占资源。
- 边界：外部库、库名指向业务库、失效claim、共享基础库、symlink、计划过期/执行前资源变化。
- 异常：外部或归属不明时禁用整库删除；基础库含未知业务数据不能整体重置，也不承诺整体删除保留其内部其他库。
- 追踪：TS-08/09/19；Plan02任务7。

### US-11 · 配置应用、中断与重开后恢复

作为用户，希望知道保存的配置是否生效，并在应用关闭或操作中断后继续处理而不重新开始。

- 来源：design §7.6–7.7；R04/R08。
- 正常：草稿/校验/应用/就绪分离，必要重建后探针验证；journal和实际资源恢复快照，允许复检后重试失败步骤。
- 边界：两应用进程、事件丢失、拉取CLI退出但daemon仍在工作、DDL结果不确定、迁移后禁止自动降级。
- 异常：显示RecoveryRequired及修复出口，不以重置数据作为默认恢复。
- 追踪：TS-16/18；Plan02任务6。

## 6. 价值

把Docker操作从命令列表收敛为可验证的状态和权限边界，让新手能重试、停止及再次启动，已有用户能安全复用环境。

## 7. 范围、需求与验收

### 7.1 流程

选择并固定本地目标→锁定工作区/依赖→预检和资源归属核验→逐DAG节点执行。全新基础库先物化凭据、拉取、启动、探针及管理账号认证，再登记绑定；已有依赖直接认证。上层先登记公共使用索引，再按绑定做专属初始化、生成配置、部署及job/业务探针。不能全局先建库再启动基础库。配置应用、停止和重置各有独立计划，不混为一次笼统重启。

### 7.4 验收测试场景

角色为后端实现/实机验收人员；全部使用明确隔离target、实例、端口、库与测试数据；包含读取型探针和写入型功能验收的区别。

#### TS-05 · 环境和容量门禁

- 目标：R01/R02；US-04。前置：三端路径/错误fixture及原生运行时，4GiB/6GiB内存样本、TCP/UDP监听、独立双盘容量样本。
- 步骤：发现CLI→读取所选目标→探测版本/能力/架构/权限/两类存储→处理各失败分支并复检。
- 结果：错误码准确；旧Compose/远端/Windows containers阻断；4GiB阻断Elastic，兼容新版本放行；未知daemon容量不会被工作区空闲替代。
- 例外：预检后端口竞争转PortConflict，不能强停其他进程或回退到全网绑定。
- 证据：未执行。

#### TS-06 · 外部观察和授权连接

- 目标：R03/R09；US-05。前置：隔离fixture模拟已有CLI MySQL/PG和同名/同路径/标签漂移资源。
- 步骤：发现→只读观察→尝试未授权初始化应拒绝→界面提交准确资源授权并验证绑定→启动上层。
- 结果：无重复基础库；实际网络/账号正确；外部容器/卷不被启停或删除；未授权库不执行DDL。
- 例外：拒绝绑定歧义及来源不明Schema；创建新实例不会显示为旧数据迁移完成。
- 证据：未执行。

#### TS-07 · 初始化每步中断恢复

- 目标：R04/R05/R09；US-06。前置：自有MySQL/PG依赖组、可控故障点、预先写入保留记录。
- 步骤：验证全新基础库先启动并认证、上层后初始化→分别在账号、各DDL/种子、Temporal Schema/Namespace及Elastic设置job处注入失败→重开后复检重试→正常重复启动/保留数据重建。
- 结果：只续跑缺失兼容步骤、不重复用户/任务种子、不丢记录；Temporal同版本工具、双库/History/Namespace设置保留；Elastic不再自动trial且错误HTTP不能吞掉。
- 例外：DDL版本不兼容进入SchemaIncompatible；建库后但归属标记前崩溃且无法证实归属进入RecoveryRequired，不认领未知库、不自动降级/重建库。
- 证据：未执行。

#### TS-08 · 精确重置及执行前竞态

- 目标：R06/R09；US-07。前置：自有专属库、无关test_db、外部库、symlink和卷替换fixture。
- 步骤：生成ResetPlan→确认准确范围→在有效计划下执行→再分别改变target/资源ID/claim/路径或等到过期重放计划。
- 结果：只有自有独占清单被清理，test_db等无关数据保留；发生变化必须重新计划；外部/系统/共用库整库删除拒绝。
- 例外：基础库包含未知业务数据或其他工作区使用者时拒绝整体重置，不能用二次输入名称绕过。
- 证据：未执行。

#### TS-09 · 场景共享与反向停止

- 目标：R04/R06；US-07。前置：MySQL被两个工作区中的两个场景及一个启动前已运行服务使用，另有外部PG；公共UsageIndex分别为完好/丢失/陈旧状态。
- 步骤：停止一个场景→尝试单独停止基础库→查看影响并确认允许的级联→普通down。
- 结果：跨工作区索引查到共用/原先运行/外部依赖并保留；陈旧心跳不视为停止，索引不完整时保守拒绝并提供修复；显式停止需列全已登记影响并逆序；down保留数据；无全局prune。
- 例外：未登记的实际连接不能被假定不存在，整实例重置仍遵循未知业务数据拒绝规则。
- 证据：未执行。

#### TS-16 · 目标变化、锁与取消

- 目标：R01/R04；US-04/11。前置：两个后端测试进程、不同workspace操作同一库claim、可切换daemon与长拉取/SQL任务。
- 步骤：并发请求→操作中切目标/资源→取消拉取与步骤间取消DDL→杀死锁持有者后重开。
- 结果：跨进程不交错破坏，稳定锁顺序无死锁；目标变化停止；取消后检查daemon实际状态；不确定SQL标RecoveryRequired；重开可恢复而不假报回滚。
- 例外：应用单实例机制不能代替后端测试中的跨进程资源锁断言。
- 证据：未执行。

#### TS-17 · 全量就绪与功能矩阵

- 目标：R07；US-06。前置：来源design §7.5每一行对应的隔离测试实例及锁定探针客户端。
- 步骤：逐组件检查daemon/job→运行全部17服务就绪探针→运行对应写读/客户端验收→分别注入错误密码、后台断连、job非0、上游不可达。
- 结果：每行有目标/版本/实际命令或API/结果/证据，任何必需探针失败撤销Ready；SearXNG上游失败显示Degraded；无客户端业务不冒充已接入。
- 例外：无healthcheck、只开放端口、首页200、Mock和跳过不得记为通过。
- 证据：未执行。

#### TS-18 · 配置应用和崩溃恢复

- 目标：R04/R08；US-11。前置：已运行旧generation、草稿端口/账号配置、事件丢失及进程中断fixture。
- 步骤：保存草稿→校验预览→应用必要重建→探针→在不同阶段中断/重开→复检后重试。
- 结果：草稿不改变运行值；applied/last_ready与实际inspect一致；无数据格式变更可验证恢复旧配置；迁移后禁止自动降级。
- 例外：restart不能作为配置已生效证据；v1已初始化账号无随机生成/密码轮换动作，更新连接值未通过真实认证不得保存为已应用。
- 证据：未执行。

#### TS-19 · 凭据及数据库归属边界

- 目标：R03/R05/R06/R09；US-05/06/07。前置：已有Canal账号密码不符、Seata/XXL独立账号、未知同名库/系统库、缺失或伪造claim、Temporal双库已有另一所有者。
- 步骤：认证/初始化→尝试跨实例claim和重置→核验服务器身份→在来源明确的空库正常初始化。
- 结果：依赖凭据来自同一绑定，专属权限可用；其他所有者/无授权/无法核验身份不得删除；旧密码/未知Schema不被悄悄修改。
- 例外：输入服务名及自定义库名不构成归属证明，外部初始化授权也不是外部整库重置授权。
- 证据：未执行。

### 7.5 假设与边界

同一服务器Temporal固定双库只允许一个所有者；已有外部Schema复用需明确授权与版本检查，不能自动迁移。没有任何开发/容器操作在本轮执行，真实环境覆盖由对应计划及发行门禁完成。
