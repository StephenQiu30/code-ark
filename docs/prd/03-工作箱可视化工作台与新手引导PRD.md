# 03 工作箱可视化工作台与新手引导 PRD

来源 design：[03 工作箱界面交互与新手引导设计](../design/03-工作箱界面交互与新手引导设计.md)。本 PRD 只对应这一份 design，面向负责人、前端开发与验收人员说明工作箱双栏界面、7 大场景启动台、四标签详情抽屉、宿主机教程与脱敏诊断导出的用户交互与验收标准；架构边界回来源 design。执行计划见 §8。

## 1. 摘要

以 `mac-gaming-toolbox` 的双栏侧边栏与温度感信息架构为原型，让编程新手在一个窗口内完成“看体检 → 点场景 → 跟进度 → 点开后台 → 复制带注释连接代码 → 出错导出脱敏诊断包”的完整闭环，并将 `MediaCrawler` 宿主机 Python 工具作为引导专题清楚安放，避免混淆容器服务。

## 2. 责任与确认

| 项目负责人 | 确认借鉴 `mac-gaming-toolbox` 交互架构、默认隐藏明文密钥与 100% 脱敏诊断原则、中文优先界面基调 |
| 开发与执行人员 | 按 [Plan 03](../plan/03-工作箱前端工作台与跨平台CI实施计划.md) 实现 React 19 + TS + Tailwind 前端组件、Vitest 用例及三端 CI 打包配置 |
| 验收与日常使用者 | 按 §7.4 场景检验 7 场景启动台、详情抽屉安全确认、宿主机/容器代码片段切换与诊断导出脱敏 |

核心规则来源于 [需求 01](../requirement/01-工作箱产品总览与核心诉求.md)（`REQ-02`、`C03–C05`）、[需求 02](../requirement/02-服务依赖与新手使用场景清单.md)（`REQ-03`、`REQ-04`）及 [设计 03](../design/03-工作箱界面交互与新手引导设计.md)。

## 3. 背景

- 编程新手常面临三类困惑：不清楚项目该启动哪几个容器、记不住分散在各个 README 中的控制台地址和默认密码、写代码时把 `127.0.0.1` 和容器内部主机名（如 `mysql` / `host.docker.internal`）混淆。
- 同时，`mediacrawler-start-local` 本质是宿主机 Python + `uv` 脚本工具而非 Docker 服务，如果混在容器卡片里会让用户误以为它缺失 `docker-compose.yml`。

## 4. 目标与成功标准

1. **双栏明确导航**：左侧固定展示“工作台（场景启动台 7 / 全部服务 17）”、“运维与诊断（环境体检 / 端口与外部冲突）”、“教程与设置（连接指南 & 教程 / 工作区设置）”；顶部全局实时展示 Docker 状态、VM 内存与运行计数。
2. **场景化一键启停与实时反馈**：选好 7 大开发场景之一并点击主按钮后，界面实时展示 `StepProgressEvent` 步进进度，明确当前处于预检、初始化还是等待健康阶段，支持跳转排查失败环节。
3. **四标签详情抽屉与默认密码保护**：所有密钥默认掩码为 `••••••`，仅主动点击切换可见；同时独立展示“宿主机直连”与“容器内部连接”片段（明确警告容器内禁用 `localhost`）；删除/重置数据按钮需准确输入服务 ID 才可激活。
4. **MediaCrawler 指引与一键脱敏诊断**：能探测本机 `git`/`uv`/目标目录并呈现补丁指引；导出的诊断 Markdown/JSON 文件对全部 `.env` 密钥及日志中碰巧泄漏的密码值 100% 替换为 `***REDACTED***`。

## 5. 使用者与场景

### US-08 · 编程新手按业务场景启动技术栈并复制连库配置

- **描述：** 作为在 IDEA 或 VS Code 里写第一份 Spring Boot / FastAPI 项目的编程新手，希望在“场景启动台”挑选对应开发组合一键启动，再直接点开管理面板并复制本地直连与容器内连接写法，以避免选错服务或填错连接地址。
- **来源与设计：** `REQ-02`、`REQ-03`、`REQ-04`；[设计 03 §7.1–§7.2](../design/03-工作箱界面交互与新手引导设计.md#72-核心视图与交互规范设计建议)。
- **讨论：** 点击场景卡片本身只选中查看详情，点击明确的“一键启动”动作按钮才触发 Docker 执行（参考 `mac-gaming-toolbox` 避免误触自动运行）；语言默认简体中文，并支持设置页切换 English 字典。
- **确认条件：**
  - 正常路径：首页完整呈现 7 个预设卡片（标明包含服务与预计内存需求），触发后顶部出现实时步进面板，完成后可在详情抽屉 Tab 1 通过外链图标打开 Web 控制台（如 Nacos `http://127.0.0.1:8840`），且独立展示宿主机（`127.0.0.1`）与容器内连接配置并带一键复制提示；
  - 边界输入：选中 `ExternalObserve` 服务时展示“外部容器运行中 (只读观察)”徽标并置顶展示替换接管入口，同时禁用启停/编辑/重置；
  - 异常提示：运行中发生步进失败时高亮出错服务及中文原因并保留重试与导出诊断入口；
  - 可访问性：弹窗与抽屉按钮均具备清晰键盘焦点、`aria-label` 与非仅靠颜色区分的文字状态标签。
- **追踪：** `TS-10`、`TS-11`；Plan 03 任务 1–2。

### US-09 · 可视化改参数、观察实时日志与输入服务名安全重置

- **描述：** 作为希望调高某个服务端口号、排查启动报错日志或清空单服务脏数据的用户，希望用中文表单改参数而不必记环境变量全名，重置数据时看到准确受影响范围提示并通过确认防呆避免误删。
- **来源与设计：** `C05`；[设计 03 §7.2](../design/03-工作箱界面交互与新手引导设计.md#72-核心视图与交互规范设计建议)。
- **讨论：** 前端表单绝不在 `localStorage` 等浏览器存储持久化明文 `.env` 密码；每次查看/保存走 Rust IPC；流式日志支持暂停滚屏和关键字筛选。
- **确认条件：**
  - 正常路径：Tab 2 表单中文展示各变量、行内标识端口冲突，支持字段旁点击“生成随机安全密钥”；Tab 3 消费 `LogLineEvent` 流式输出并支持过滤与复制报错行；Tab 4 展示上下游依赖、一键打开持久化目录与重置弹窗；
  - 边界输入：默认密码在 Tab 1 掩码渲染为 `••••••`，点击小眼睛切换才短暂明文显示；重置弹窗在输入框未严格匹配目标服务 ID 前，危险确认按钮保持 disabled；
  - 异常提示：对 `temporal`/`xxjob`/`seata` 显示“仅清理专属数据库与日志”；对 `mysql`/`pgsql` 明确列出受影响上层服务级联警告；
  - 非破坏性：任何界面交互出错不会丢失已填表单草稿或绕过 Rust 二次确认直接调破坏性命令。
- **追踪：** `TS-11`；Plan 03 任务 2。

### US-10 · 导出 100% 脱敏诊断报告与查看宿主机工具/新手教程

- **描述：** 作为环境排查遇到困难需要发给同学/社区求助的用户，或想跑 `MediaCrawler` 爬虫工具的用户，希望能导出不含自己密码的诊断报告，并在工作箱内看懂跨网段区别和 `MediaCrawler` 启动前置步骤。
- **来源与设计：** `C04`、`C05`、`Q01`；[设计 03 §7.2](../design/03-工作箱界面交互与新手引导设计.md#72-核心视图与交互规范设计建议)。
- **讨论：** 除了将 `.env` 导出表格脱敏之外，若某容器最近 100 行启动日志里不小心打印出了连接串密码（如带密码的 JDBC/DSN URL），诊断导出器也必须把该密码字符串在日志正文里一并替换为 `***REDACTED***`。
- **确认条件：**
  - 正常路径：导出流程收集系统版本、Docker 信息、端口占用、配置键结构与运行服务最近 100 行日志，输出 JSON 与 Markdown 报告；在指南中心可看到图文/步骤清晰的“本地代码 vs 容器代码地址区别”、`MediaCrawler` 宿主机 `git`/`uv` 检测及固定 commit `380b426000aac3d612837ed72c99808347dc94c9` + 双 `.patch` 应用指南、及未公证 macOS App 打开引导；
  - 边界输入：空密码或短字符环境变量不触发误替换或空字符串死循环脱敏；重叠长度密钥从长到短优先匹配脱敏；
  - 非破坏性：前端与导出产物里不包含任何 `.env` 原文密码。
- **追踪：** `TS-12`、`TS-13`；Plan 03 任务 2（及 Rust 侧诊断构建模块）。

## 7. 范围、需求与验收

### 7.1 使用或服务流程

1. **顶部全景监测**：应用就绪即拉取环境体检与服务快照，渲染工作区健康摘要、运行计数器及右侧抽屉上下文。
2. **场景/目录双轨操作**：用户既可从 7 个场景卡片批量启动，也可切到 17 个服务目录按 4 类筛选精细控制。
3. **四标签服务管理 + 运维指南**：进入任一服务即展开 430px 详情抽屉覆盖连接、参数、日志与依赖重置；侧栏另提供端口冲突总览、脱敏诊断导出、教程中心与工作区设置。

#### TS-12 · 诊断压缩/报告导出 100% 密钥脱敏验证

- **目标：** 核对 `PRD03-R05`、`US-10`。
- **前置条件：** 临时工作区中配置好 `mysql`、`pgsql`、`nacos`、`searxng`、`elastic` 的 `.env` 真实测试秘密值，并在模拟日志行中刻意嵌入其中若干秘密值及空值占位。
- **角色：** 安全审校 / 验收人员。
- **步骤与结果：**
  1. 执行 `build_redacted_diagnostics_bundle` 构建 JSON 与 Markdown 诊断结果；
  2. 全文检索断言两份结果中包含 `"***REDACTED***"` 脱敏标志；
  3. 遍历测试 `.env` 中每个非空敏感密码/token，断言其在 `bundle_json` 与 `bundle_markdown` 中的出现次数严格为 `0`；
  4. 确认存在包含短前缀关系的重叠密码值时，长密码未被短密码部分切分漏曝。
- **例外：** 某 `.env` 中存在空值密钥（`EMPTY_KEY=`）时不得将诊断报告中的其他空位置或字母误替换为脱敏符。
