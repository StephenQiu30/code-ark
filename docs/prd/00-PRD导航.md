## 2. 阅读与维护规则

1. **先读来源设计，再看 PRD 验收**：技术数据结构、目录约束、状态机与覆盖层语法归来源 `design` 维护；本目录只写面向角色的可观察行为、范围边界、`US` 用户故事与 `TS` 测试场景。
2. **需求 / 验收 ID 稳定性**：`PRD01-Rxx`、`PRD02-Rxx`、`PRD03-Rxx`、`US-01..10` 与 `TS-01..13` 保持稳定，后续扩充只追加新编号，不复用旧编号。
3. **跨文档变更闭环**：若发现范围或技术边界需修改，先更新对应的 `design`（并同步确认需求 `requirement`），再修订唯一对应 `prd` 与下游 `plan`。
4. **实事求是登记证据**：遵循 [测试场景模板](../templates/03-测试场景模板.md)，所有未实机/命令行跑通的场景统一保留 `证据：未执行`，禁止以 Mock 或纯静态检查替代真实容器联调结论。
